Owner: Federico Viavattene. **Chat with him in Spanish; all app UI text, code comments and docs stay in English.**
Purpose: simulate Riftbound TCG matchups (his deck vs. archetype opponents) to improve his play.

## Architecture: one app, one engine, two deck stores

`docs/` is the only app and `docs/engine.js` the only engine (the PowerShell engine, the console tool and `web/` were retired in Oct 2026). PC and phone run the same files in the browser.

| | PC | Phone PWA |
|---|---|---|
| How it runs | `RunWebUI.bat` → `WebServer.ps1` (`HttpListener`, localhost ports 8787–8796) serves `docs/` | GitHub Pages serves `docs/`; `docs/sw.js` caches it for offline |
| Decks | `Decks/**/*.csv`, through `GET`/`PUT`/`DELETE /api/decks` (`DeckFiles.psm1`) → `FileDeckStore` in `engine.js` | IndexedDB → `DeviceDeckStore`, merged with `docs/decks.json` on every start (`mergeSeedDecks`) |
| Card data / bans | `docs/carddatabase.json`, `docs/banned.json` (canonical, no other copies) | same files |

- `engine.init()` picks the store: on `localhost` it probes `api/decks`; if that answers JSON it's the PC (`engine.storageKind === 'files'`), otherwise IndexedDB (`'device'`).
- In `'files'` mode `app.js` does not register the service worker (and unregisters leftovers); `sw.js` never intercepts `/api/`.
- Deck record shape (both stores): `{ id, name, category, isMyDeck, rows }`, id = path under `Decks/` without `.csv` (`MyDeck/X`, `Opponents/<Category>/X`). `DeckFiles.psm1` validates ids so writes can't escape `Decks/`.
- `docs/decks.json` is generated by `UpdatePhoneDecks.ps1` (run by `PushToGitHub.bat`), which also bumps `CACHE_NAME` when the snapshot changed.
- Seed merge on the phone (IndexedDB v2, `meta` store keeps each seed deck's row fingerprint as last seeded): new seed decks are added (an existing deck with that id is kept), a changed seed deck replaces the phone copy only if that copy is unedited since it was seeded, a seed deck deleted on the phone stays deleted.

**Standing rules — easy to forget, always check:**
1. **Bump `CACHE_NAME` in `docs/sw.js`** (currently `riftbound-sim-v5`) on every change under `docs/`. Otherwise installed phones keep serving the stale cached copy. (`UpdatePhoneDecks.ps1` only bumps it for `decks.json` changes.)
2. `docs/app.js` registers the service worker with a guarded `controllerchange` → `window.location.reload()`. That fixes "new HTML + old cached JS" after an update. Don't remove it.
3. Don't fabricate card behavior. Cards reduce to Energy/Power/Might/Domain + optional Tag (`Remove:N`, `Buff:N`, `Draw:N`, `Shield:N`). Only 2 Legend abilities are modeled (Rengar, Draven), data-driven via `legendAbility` in `docs/carddatabase.json`. New abilities must use real rules text and existing triggers (`OnUnitPlayed`, `OnCombatWin`).
4. Hard rules already modeled: Victory Score 8 is a hard ceiling (every score update is clamped), Final Point rule at 7+, Runes/Battlefields/Legend are never drawn.

## Key constants and behavior
- Run sizes live only in `RUN_SIZES` in `docs/engine.js` (1000 games single, 200 Bo3 matches, 500 games per opponent in the matrix); `app.js` fills the button and mode-card labels from it.
- Every run is seeded (mulberry32, `this.rng`); results report `seed` and a 95% Wilson range (`winrateLow`/`winrateHigh`). The matrix replays the same seed for each opponent. The UI has an optional Seed field to replay a run.
- Game model (Oct 2026): 1v1, 2 battlefields, opening hand 4 + mulligan, runes capped at the Rune count, per-unit state (base/battlefield, exhausted, temp buffs, shield, gear), Conquer/Hold scoring, Final Point rule, Burn Out per rule 431, draws after 40 rounds. Rules verified against Core Rules / Quick Start (via rulespal.com) and RiftJudge rulings. Power costs, Reactions, Accelerate/Ganking and battlefield abilities are not modeled.
- Modes: single opponent, best-of-3 match, matchup matrix (matrix has no recommendation panel by design).
- Matchup recommendation + 10-card sideboard suggestion are heuristics from existing stats, not a re-simulation.
- Deck editor ("Decks" tab): `engine.getDeck/saveDeck/deleteDeck/searchCards/cardRow/checkDeck/deckIdFor`. Nothing is written until Save.
- Deck legality: exactly 1 Legend, 12 Runes, 3 Battlefields, ≥40 Main Deck, ≤3 copies, only real cards from `docs/carddatabase.json`.
- Opponent decks live in `Decks/Opponents/{Aggro,Midrange,Control}`; the user's decks in `Decks/MyDeck`. Text-list import: the app's "Import" tab (`engine.importDeck` → CSV on the PC, IndexedDB on the phone).

## Deck picker (category → legend photo mosaic)
- The visible control is a `.deck-picker-trigger` button; the real `<select id="myDeck">` / `#opponentDeck` stays as hidden source of truth (same pattern as the mode cards / hidden `#simMode`): custom UI sets `.value` and dispatches `change`, so downstream code is unchanged.
- Decks are grouped by **Legend identity** (the deck's own `Type==='Legend'` row `Name`), exposed as `legend` by `docs/engine.js` (`legendNameOf`/`listDecks`). Several decks with the same Legend collapse into one tile showing "N decks available", then a variant list.
- Legend art is **hotlinked** from Piltover Archive: `https://cdn.piltoverarchive.com/cards/<CODE>.webp?width=420`, via the `LEGEND_ART` table in `docs/app.js`. **When adding a deck with a new Legend, add its `LEGEND_ART` entry** (search the exact Legend name on piltoverarchive.com, take the base print's code); without it the tile shows an initial-letter placeholder (not broken). Images are cached offline only after being viewed once online.

## Working in this repo
- Windows PC, Windows PowerShell 5.1 compatibility matters (e.g. no `ConvertFrom-Json -AsHashtable`; don't make `[string[]]` parameters `Mandatory`; use `ConvertTo-Json -InputObject` so one-element arrays stay arrays).
- After editing `WebServer.ps1` / `DeckFiles.psm1` / `UpdatePhoneDecks.ps1`, actually run them (`powershell.exe` is available).
- JS checks: `node --check docs/app.js docs/engine.js docs/sw.js`. UI checks: `.claude/launch.json` has a `pc-webserver` config (`WebServer.ps1 -NoBrowser`) for the browser pane; for phone mode serve `docs/` with any static server (no `api/decks` → IndexedDB). Python is not installed; Node is.
- Publish with `PushToGitHub.bat` (or plain `git push origin main`). GitHub Pages takes ~1 minute to redeploy.

Phase 2 = Power costs by rune domain, card rules text + keywords (Reactions, Accelerate, Ganking...), battlefield abilities, turn-by-turn replay. Phase 3 = data pipeline (new sets, tournament/RQ results, meta screen, real-games journal). Phase 4 = simulation-backed recommendations, calibration, ML.
- Phase 1 is done (engine bugs from the Oct 2026 review fixed, seeded RNG, larger runs with 95% ranges, deck editor, seed merge on phones). Still open from that review: Power costs are ignored; untagged spells have no effect (needs Tags or card text); recommendations ignore the opponent's actual cards (Phase 4: simulation-backed swaps).
- Tags (Remove/Buff/Draw/Shield) are mostly blank for real cards; fill by hand where a matchup needs them (e.g. Rampage `Buff:5` was lost on the Rengar re-import). The card database has no rules text yet.
- The 9 rebuilt archetype opponent decks are legal real-card decks but not verified tournament lists (Sett/Lillia/Vex are).
- More Legend abilities only where they fit the engine's existing triggers; Empower/XP, exhaust/ready, Equip and tokens would need new engine mechanics first.
- Adding more decks per Legend (user plans this for variety) — the picker already handles it.
- Google login was discussed and deliberately not built (would need real hosting/OAuth).
