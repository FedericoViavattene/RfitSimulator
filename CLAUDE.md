# Riftbound Deck Simulator — project guide for Claude Code

Owner: Federico Viavattene. **Chat with him in Spanish; all app UI text, code comments and docs stay in English.**
Purpose: simulate Riftbound TCG matchups (his deck vs. archetype opponents) to improve his play.
GitHub repo: https://github.com/FedericoViavattene/RfitSimulator (the "Rfit" spelling is real). Branch `main`. Phone app is served by GitHub Pages from `main` → `/docs`.

## Architecture: one app, one engine, two deck stores

`docs/` is the only app and `docs/engine.js` the only engine (the PowerShell engine, the console tool and `web/` were retired in Oct 2026). PC and phone run the same files in the browser.

| | PC | Phone PWA |
|---|---|---|
| How it runs | `RunWebUI.bat` → `WebServer.ps1` (`HttpListener`, localhost ports 8787–8796) serves `docs/` | GitHub Pages serves `docs/`; `docs/sw.js` caches it for offline |
| Decks | `Decks/**/*.csv`, through `GET`/`PUT`/`DELETE /api/decks` (`DeckFiles.psm1`) → `FileDeckStore` in `engine.js` | IndexedDB → `DeviceDeckStore`, merged with `docs/decks.json` on every start (`mergeSeedDecks`) |
| Card data / bans | `docs/carddatabase.json`, `docs/banned.json` (canonical, no other copies) | same files |

- `engine.init()` picks the store: on `localhost` it probes `api/decks`; if that answers JSON it's the PC (`engine.storageKind === 'files'`), otherwise IndexedDB (`'device'`).
- In `'files'` mode `app.js` does not register the service worker (and unregisters leftovers); `sw.js` never intercepts `/api/`.
- Deck record shape (both stores): `{ id, name, category, isMyDeck, rows }`, id = path under `Decks/` without `.csv` (`MyDeck/X`, `Opponents/<Category>/X`). `DeckFiles.psm1` validates ids so writes can't escape `Decks/`.
- `docs/decks.json` is generated by `UpdatePhoneDecks.ps1` (run by `PushToGitHub.bat`), which also bumps `CACHE_NAME` when the snapshot changed.
- Seed merge on the phone (IndexedDB v2, `meta` store keeps each seed deck's row fingerprint as last seeded): new seed decks are added (an existing deck with that id is kept), a changed seed deck replaces the phone copy only if that copy is unedited since it was seeded, a seed deck deleted on the phone stays deleted.

## Card data pipeline (Phase 2, Oct 2026)
- Source of truth for mechanics: Riot's official card gallery (`riftbound.leagueoflegends.com/en-us/card-gallery/`, Next.js data JSON). `node tools/build-card-data.mjs [saved-gallery.json]` (Node, dev-only) adds to each `docs/carddatabase.json` entry: `code` (base print collector code), `keywords` (only keyword-only lines, e.g. `{"Assault":2,"Accelerate":{energy,power}}`), `equip`, and `ability`/`abilityPartial` from `tools/card-abilities.json`.
- `tools/card-abilities.json` = hand-curated abilities in the engine's op vocabulary (see "CARD ABILITIES"/`runOp` in `engine.js`), each with a `hash` of the official text; the builder warns and drops an ability whose text changed. Name matching: Legends are "Champion, Title" (champion is one of the gallery `tags`), signature spells drop the champion subtitle, plus `NAME_FIXES`.
- **The rules text is not stored in the repo** (copyright): only mechanics. The app shows the official card image (`cardImageUrl(code)` → Piltover Archive CDN) where the text is visible.
- Card precedence in the engine: curated `ability` > deck row `Tag` (ignored when the card has an ability; the editor flags it) > nothing. Old hand-made deck Tags were wrong vs. the official text and were cleared.

**Standing rules — easy to forget, always check:**
1. **Bump `CACHE_NAME` in `docs/sw.js`** (currently `riftbound-sim-v6`) on every change under `docs/`. Otherwise installed phones keep serving the stale cached copy. (`UpdatePhoneDecks.ps1` only bumps it for `decks.json` changes.)
2. `docs/app.js` registers the service worker with a guarded `controllerchange` → `window.location.reload()`. That fixes "new HTML + old cached JS" after an update. Don't remove it.
3. Don't fabricate card behavior. New abilities go in `tools/card-abilities.json`, written from the card's official text using existing ops/triggers (or new engine ops), then `node tools/build-card-data.mjs`. Mark `"partial": true` when only part of the text is modeled.
4. Hard rules already modeled: Victory Score 8 is a hard ceiling, Final Point rule, Runes/Battlefields/Legend are never drawn.

## Key constants and behavior
- Run sizes live only in `RUN_SIZES` in `docs/engine.js` (1000 games single, 200 Bo3 matches, 500 games per opponent in the matrix); `app.js` fills the button and mode-card labels from it. Matrix ≈1 s on the PC, slower on phones.
- Every run is seeded (mulberry32; `startRun(seed)` resets `this.rng` and `gameCounter`); results report `seed` and a 95% Wilson range. The matrix replays the same seed per opponent. Optional Seed field in the UI.
- Replay: `engine.replayGame(my, opp, { mode, seed, gameIndex })` re-runs the same run with `this.replay = { index, log }` and returns that game's events (`note()` calls); nothing is stored. Single and Bo3 modes (match rows carry each game's `index`).
- Game model (Phase 2): 1v1; each player brings one of their 3 battlefields (random, no repeats in a Bo3); opening hand 4 + mulligan; runes with domains (Energy = exhaust, Power = recycle a rune of the card's domain to the Rune Deck bottom; two-domain cards accept either domain); unspent runes fund Reactions on the opponent's turn; per-unit state; keywords Accelerate/Ambush/Assault/Backline/Deflect/Ganking/Reaction/Action/Shield/Tank/Temporary; combat reaction window (defender then attacker); counterspells; control lasts while you have units there; Conquer/Hold; battlefield abilities; Burn Out per rule 431; draws after 40 rounds. Rules checked against Core Rules / Quick Start (via rulespal.com) and RiftJudge rulings.
- Not modeled: Hidden, Legion, Level/XP, Empower costs, Vision/Predict, Repeat, move/bounce effects, gold tokens.
- Modes: single opponent, best-of-3 match, matchup matrix (matrix has no recommendation panel by design).
- Matchup recommendation + 10-card sideboard suggestion are heuristics from existing stats, not a re-simulation.
- Deck editor ("Decks" tab): `engine.getDeck/saveDeck/deleteDeck/searchCards/cardRow/checkDeck/deckIdFor/cardInfo`. Nothing is written until Save. Card names anywhere (`.card-link`) open the card viewer (`engine.cardInfo`).
- Deck legality: exactly 1 Legend, 12 Runes, 3 Battlefields, ≥40 Main Deck, ≤3 copies, only real cards from `docs/carddatabase.json`.
- Opponent decks live in `Decks/Opponents/{Aggro,Midrange,Control}`; the user's decks in `Decks/MyDeck`. Text-list import: the app's "Import" tab (`engine.importDeck` → CSV on the PC, IndexedDB on the phone).

## Deck picker (category → legend photo mosaic)
- The visible control is a `.deck-picker-trigger` button; the real `<select id="myDeck">` / `#opponentDeck` stays as hidden source of truth (same pattern as the mode cards / hidden `#simMode`): custom UI sets `.value` and dispatches `change`, so downstream code is unchanged.
- Decks are grouped by **Legend identity** (the deck's own `Type==='Legend'` row `Name`), exposed as `legend` by `docs/engine.js` (`legendNameOf`/`listDecks`). Several decks with the same Legend collapse into one tile showing "N decks available", then a variant list.
- Legend art is hotlinked from Piltover Archive by the Legend's `code` in `carddatabase.json` (`legendArtUrl` → `engine.cardInfo`); no per-legend table to maintain. Without a code the tile shows an initial-letter placeholder. Images are cached offline only after being viewed once online.

## Working in this repo
- Windows PC, Windows PowerShell 5.1 compatibility matters (e.g. no `ConvertFrom-Json -AsHashtable`; don't make `[string[]]` parameters `Mandatory`; use `ConvertTo-Json -InputObject` so one-element arrays stay arrays).
- After editing `WebServer.ps1` / `DeckFiles.psm1` / `UpdatePhoneDecks.ps1`, actually run them (`powershell.exe` is available).
- JS checks: `node --check docs/app.js docs/engine.js docs/sw.js`. UI checks: `.claude/launch.json` has a `pc-webserver` config (`WebServer.ps1 -NoBrowser`) for the browser pane; for phone mode serve `docs/` with any static server (no `api/decks` → IndexedDB). Python is not installed; Node is. The engine also runs in Node for quick checks (set `engine.cardDatabase`, `engine.bannedSet` and a stub `engine.store`).
- Publish with `PushToGitHub.bat` (or plain `git push origin main`). GitHub Pages takes ~1 minute to redeploy.
